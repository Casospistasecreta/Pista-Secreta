# Pista Secreta: internationalization guide

This project supports Brazilian Portuguese (`pt-BR`), English (`en`), and
Spanish (`es`). Portuguese is the source language and the fallback. Language
selection does not change URLs or case slugs.

## How the architecture works

- `src/i18n/LanguageProvider.tsx` owns the active language, the `t(key)` helper,
  lazy loading of English and Spanish resources, and the saved preference
  `pista-secreta:language` in `localStorage`. It also sets `<html lang>`.
- `src/i18n/site/` contains landing-page and personalized-offer copy;
  `src/i18n/ui/` contains shared interface and investigation-app copy; and
  `src/i18n/quiz/` contains quiz copy. Each folder has one dictionary per
  language. Keys are flat names such as `site.casePeaoName`,
  `quiz.introTitle`, and `investigation.deviceLocked`.
- The personalized-offer dictionaries are shared from
  `lib/personalizados-core/src/translations.ts`, so the API and page use the
  same wording.
- `src/i18n/types.ts` defines `Lang`, `Localized<T>`, `pick()`, and
  `resolveLocalized()`. If an individual translation is absent, `pt-BR` is
  returned rather than an empty value or an internal key.
- `src/i18n/metadata.ts` updates the document title, meta description, Open
  Graph and Twitter titles/descriptions, and locale. The landing page and the
  digital investigation route supply metadata for the active language.
- Case content lives in `src/investigacao/cases/`; the data is resolved to
  plain strings by the device provider. The registry in
  `src/investigacao/cases/registry.ts` maps stable slugs to cases. Routes remain
  `/investigacao/:slug`.

## Add translations to a new case

1. Add the case data under `src/investigacao/cases/`. For a case with multiple
   data areas, use focused files such as `messages.ts`, `social.ts`, and
   `final-answer.ts`, then assemble them in `index.ts`.
2. Use the existing `L(ptBR, en, es)` helper from that case's `helpers.ts`, or
   import it from `src/investigacao/cases/localized.ts` for simple cases:

   ```ts
   title: L("Título em português", "English title", "Título en español"),
   ```

   Wrap every player-facing string, including dates, media captions, lock hints,
   labels, feedback, and reports. Use `calendar()` for abbreviated Portuguese
   month labels; use `L()` for full dates and other locale-specific wording.
3. Keep stable identifiers and behavior unchanged: case slug, message and
   evidence IDs, passcodes, unlock keys, FEN positions, answer option IDs,
   correct answers, analytics names, and media paths. Names, handles, product
   brands, and codes remain as proper names or identifiers when appropriate.
4. Import the case in `cases/registry.ts` and add it to `CASES`. If it also
   needs a landing-page product card, add its copy to all three `site`
   dictionaries and wire the checkout and analytics metadata separately.
   Never translate or replace checkout URLs as part of localization.
5. Open `/investigacao/<slug>` directly with no saved language and with `en`
   and `es` saved. Check every app, lock, hint, challenge, evidence item, and
   final-answer screen after switching languages and reloading.

Text embedded in image, audio, video, or PDF files is not translated by code.
If those files need localization, prepare separate approved media assets.

## Add a language

1. Add the locale code to `Lang` in `src/i18n/types.ts` and add its optional
   property to `Localized<T>`.
2. Create matching `site/<code>.ts` and `ui/<code>.ts` dictionaries. Copy every
   key from the Portuguese dictionaries and translate its value; preserve
   interpolation placeholders such as `{count}` and `{duration}`.
3. Add a lazy import branch in `LanguageProvider.loadDictionary()` and accept
   the locale in `readSavedLanguage()`.
4. Add the language option to `LanguageSwitcher.tsx`.
5. Add the locale tag to `updatePageMetadata()` in `metadata.ts`, and add the
   new locale to the `L()` helper shape used by case data.
6. Run `pnpm --filter @workspace/pista-secreta run i18n:check`,
   `pnpm --filter @workspace/pista-secreta run typecheck`, and
   `PORT=4173 BASE_PATH=/ pnpm --filter @workspace/pista-secreta run build`.
   Verify the default/fallback language, direct case routes, saved preference,
   metadata, and responsive layouts in the new language.

## Find untranslated or missing text

- Run `pnpm --filter @workspace/pista-secreta run i18n:check`. It checks for
  missing, extra, or duplicate site/UI/quiz keys and shared personalized-copy
  keys across the three dictionaries, then checks literal translation-key
  calls in source.
- TypeScript checks that calls to `t()` use a declared key. In development,
  the browser console also warns when a loaded dictionary is missing a key and
  falls back to Portuguese.
- Review visible JSX text and accessibility labels in the site and
  investigation components. Player-facing literals belong in `t("...")` or
  localized case data; do not leave copy directly in JSX or as a plain
  Portuguese string in a case object.
- Switch the preview through all languages and inspect dialogs, empty/error
  states, mobile layouts, media captions, and screens reached only after
  unlocking content. Key parity cannot identify a mistranslated value or a
  hard-coded literal that never calls `t()`.
